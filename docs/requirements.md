# 要件定義

## 1. システム概要

### 1.1 目的

本アプリは、日常的な挨拶や連絡をワンタップで気軽に行うためのアプリである。

### 1.2 想定ユーザー

- LINE等のSNSを利用している全てのユーザー

### 1.3 想定端末
 
PCでも利用可能だが、基本的にはスマホ等のモバイル端末で利用するアプリとする。

---

## 2. 機能要件

### 2.1 ログイン

ユーザーはIDとパスワードを使用してログインできる。

#### 正常時

正しいIDとパスワードの場合、
ログイン後のメッセージ送信画面へ遷移する。

#### 異常時

以下の場合はログインできない。

- IDが存在しない
- パスワードが間違っている

ログインに失敗した場合はエラーメッセージを表示する。
上記に該当する場合、エラーメッセージは「IDまたはパスワードが間違っています」で統一。

ユーザー情報は、ID, name, password。

---

### 2.2 新規ユーザー登録

ログイン画面に「新規ユーザー登録はこちら」と青文字で書かれたリンクを置き、
そのリンクを押すことで遷移する。

ID, name, password, password(確認用)

を入力フォームとして新規ユーザー登録を行う。

ID、パスワードともに、英字と数字からなる6文字以上とし、空白は使用不可。
また、IDはユニーク、nameは重複可とする。

#### 正常時

「ユーザー登録が完了しました」というポップアップが表示され、ログイン画面に遷移する。

#### 異常時

以下の場合はユーザー登録できない

- 既に使用されているIDで登録

「このIDは既に使用されています」と表示

- password と password(確認用) が異なる

「パスワードが間違っています」と表示

---

### 2.3 チャット送信画面

チャット送信画面では、あらかじめ登録されているメッセージのテンプレート一覧が表示される。
このテンプレートはユーザーごとに登録することができる。

メッセージテンプレートをタップすると、フォロワーにメッセージを送信できる。
インスタグラムのストーリーやXのポストのように、基本的には全てのフォロワーに同時にメッセージが送信される。

また、LINEのようにメッセージを自由に入力できる欄も作り、
入力した後に「送信」ボタンを押すと、入力した内容が送信される。

---

### 2.4 チャット閲覧画面

ログイン中はWebSocketで新着メッセージ通知を受信し、チャットルーム一覧および
表示中の該当チャットルームを再読み込みなしで最新状態へ更新する。
WebSocketが切断された場合は自動的に再接続する。

#### 2.4.1 チャットルーム一覧画面

チャットを受信したユーザー一覧が表示される。

１番上は、自分が送信したメッセージの履歴を確認するためのチャットルームとする。
２番目以降は、未読のチャットが存在するユーザーが上に表示され、
未読のチャットが存在しないユーザーが下に表示される。
さらに、チャット送信時間で降順（新着が上）にソートされた状態で表示される。
各チャットルームには最新メッセージと、その送信時間を日本時間で表示する。
最新メッセージが長い場合は、送信時間に重ならない位置で末尾を「...」として省略する。

チャットルームを選択すると、各チャットルームの画面に遷移する。


#### 2.4.2 各チャットルーム画面

個人のチャットルームに遷移した後の画面。
該当ユーザーから受信したチャット履歴を確認できる。

チャットの内容と送信された時間が表示される。

自分が送信したチャットの履歴を確認するためのチャットルームでも同様に、
自分が送信したチャットの内容と送信した時間を確認できる。

また、自分が送信したチャットでは、チャットをタップすることで、ボトムシート形式で
そのチャットを閲覧したユーザー一覧をを確認することができる。

チャット履歴は、送信時間で昇順（新着が下）にソートされた状態で表示される。

表示対象は過去1週間以内のチャットに限る。
他ユーザーのチャットについては、友だちになった日時以降に送信されたもののみ表示する。

---

### 2.5 検索画面

IDを入力することで、ユーザーを検索することができる。
検索は完全一致検索とし、IDが完全一致している場合のみ、ヒットする。

検索結果として表示されるユーザーの、右端に以下の仕様のボタンを作る。

「友だち」「リクエスト中」のいずれの状態でもないユーザーは、「フォロー」ボタン、
「友だち」である場合は、「フォロー解除」ボタン、
「リクエスト中」である場合は、「リクエスト中」ボタンが表示される。

フォローボタンは、タップするとフォローリクエストを送信することができる。

フォロー解除ボタンは、タップすると「本当に解除しますか？」というポップアップが表示され、
その後フォロー解除を行う。

リクエスト中ボタンは、タップすると「フォローリクエストを棄却しますか？」というポップアップが表示され、
その後、フォローリクエストが棄却される。

### 2.6 アカウント画面

#### 2.6.1 アカウントメイン画面

アカウント関連の情報の確認、編集ができる。

「友だち」の数と一覧を閲覧できる。友だち数は友だち一覧の見出しに表示する。

チャットのやり取りは、「友だち」とのみ行うことができ、
「友だち」は相互フォローである前提とする。
（インスタグラムやXのように一方的にフォローし、
チャットを閲覧するなどは不可。）

友だち一覧の一番上に「リクエスト」という項目を作り、
これをタップすると、自分宛のフォローリクエスト一覧を確認できる。
フォローリクエストが存在する場合は、項目の右側に未読メッセージと同じマークを表示する。

フォローリクエストの右端に、「許可」ボタンと「却下」ボタンを作り、
許可ボタンを押すと、自動的に相互フォロー状態となり、「友だち」になる。
却下ボタンを押すと、「本当にこのリクエストを却下しますか？」というポップアップが表示され、
その後、リクエストが棄却される。

本画面の右上に歯車のマークを表示し、これをタップすると設定画面に遷移する。

#### 2.6.2 設定画面

各種設定を行うことができる。

とりあえす、「テンプレート」と「ログアウト」を作成する。
テンプレートはアイコンや説明文を付けず、シンプルなメニュー項目として表示する。

ログアウトは、白色の背景に赤文字で「ログアウト」と表示された項目とし、
タップすると「本当にログアウトしますか？」というポップアップが表示され、
その後ろグアウトする。

#### 2.6.3 テンプレート画面

一番上に、登録するテンプレートの内容を入力する欄と、その右端に「登録」ボタンを用意する。

また、その下には既存のテンプレート一覧を表示する。

各テンプレートの右側には、「削除」ボタンと「≡」マークを用意する。

削除ボタンは、押すと「このテンプレートを削除しますか？」というポップアップが表示され、
その後、該当するテンプレートを削除する。

「≡」マークは、長押しして、スライドすることで、テンプレートの順番を変更することができる。
この順番は、チャット送信画面のテンプレート一覧にも適応される。

## 3. 画面要件

### 3.1 画面一覧

| 画面 | URL |
|---|---|---|
| ログイン | `/login` |
| 新規ユーザー登録 | `/register` |
| チャット送信 | `/chat` |
| チャット閲覧 | `/view` |
| ユーザーごとのチャット閲覧 | `/view/:user_id` |
| 検索 | `/search` |
| アカウント | `/account` |
| 設定 | `/setting` |
| テンプレート | `/setting/templete` |

ログイン後の画面は、下部に画面遷移のタブがあり、項目は
「送信」「閲覧」「検索」「アカウント」
の４つとする。

各タブは文字ではなく、それぞれ紙飛行機、吹き出し、虫眼鏡、人物のアイコンで表示する。

ログイン後は、デフォルトでチャット送信画面に遷移する。

## 5. 共通要件

### 5.1 認証

ログインしていないユーザーは、
ログイン、新規ユーザー登録画面以外の画面を利用できない。

ログイン後は、アクセストークンをReactのメモリ上に保持し、有効期限は60分とする。
リフレッシュトークンはHttpOnly Cookieに保持し、有効期限は最終利用から60日とする。

アプリ起動時およびアクセストークン失効時は、リフレッシュトークンを使用して
アクセストークンを再発行する。再発行時にはリフレッシュトークンもローテーションし、
使用済みトークンの再利用を検出した場合は、同じログインセッションを失効させる。

ユーザーが明示的にログアウトした場合は、サーバー側のログインセッションを失効させ、
リフレッシュトークンCookieを削除する。

### 5.2 認可

ユーザーは自身の権限で許可されている操作のみ実行できる。

画面上でボタンを非表示にするだけでなく、
サーバー側でも権限を検証する。

### 5.3 エラー表示

入力エラーが発生した場合、
ユーザーが修正方法を理解できるメッセージを表示する。

### 5.4 データ保持

ユーザーが画面を再読み込みしても、
登録済みのデータが失われないこと。

### 5.5 日時

日時はデータベースへUTCで保存し、画面上では日本時間で表示する。

---

## 6. 非機能要件

### 6.1 セキュリティ

- パスワードを平文で保存しない
- 認証されていないユーザーからデータを保護する
- ユーザー入力を安全に処理する

### 6.2 UI

- スマホ等のモバイル端末で問題なく利用できる
- PCで問題なく利用できる
- 色は青をベースカラーとする

### 6.3 パフォーマンス

通常の利用において、
ユーザーが著しい待ち時間を感じないこと。

---

## 7. 対象外

現時点では以下は実装対象外とする。

- LINE連携
- 外部求人サービスとの連携
- AIによる候補者評価
- スマートフォンネイティブアプリ
